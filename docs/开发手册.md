# 开发手册与接口约定

## 1. 环境与模块划分

Python 3.10+，GUI 依赖标准库 Tkinter。算法模块不依赖 Tkinter，导入 `saes.core`、`saes.modes`、`saes.attack` 不会创建窗口。

| 模块 | 职责 |
| --- | --- |
| `core.py` | GF(2^4)、S 盒、行移位、列混淆、密钥扩展、16 位分组加解密与逐步轨迹 |
| `encoding.py` | 严格格式解析、ASCII、字节分组、PKCS#7 |
| `modes.py` | 单／双／三重加密、CBC、CBC 篡改比较 |
| `attack.py` | 中间相遇搜索、候选过滤、进度和取消 |
| `records.py` | 当次操作快照与 JSON／文本序列化 |
| `gui.py` | 参数采集、结果展示、后台任务与用户反馈 |

对外接口的无效数值和格式主要抛出 `ValueError`；GUI 在操作边界捕获并提示。程序中间状态使用整数表示，按需格式化为 HEX/BIN。

## 2. S-AES 参数

- 输入位序从高位至低位，`0xABCD` 的状态矩阵是 `[[A,C],[B,D]]`。
- S 盒按输入值 `0..F` 顺序：`9 4 A B D 1 8 5 6 2 0 3 C E F 7`。
- 逆 S 盒：`A 5 9 B 1 7 8 F 6 0 2 3 C 4 D E`。
- 列混淆矩阵 `[[1,4],[4,1]]`；逆矩阵 `[[9,2],[2,9]]`。
- GF(2^4) 模多项式 `x^4+x+1`，二进制 `10011`。
- 密钥扩展轮常数 `0x80`、`0x30`。
- 初始轮密钥加后，第一轮执行 NS、SR、MC、AK；第二轮执行 NS、SR、AK。
- 解密严格逆序执行，不采用修改轮密钥的等价解密结构。

`_` 开头的函数是内部接口；公开接口验证输入范围后，内部计算复用预先展开的轮密钥。GF 乘法函数生成乘 2、4、9 的小查表，列混淆无需重复进行多项式约减。

## 3. 核心公开接口

| 函数 | 参数 | 返回 |
| --- | --- | --- |
| `encrypt_block(block, key)` | 两个 16 位整数 | 16 位密文整数 |
| `decrypt_block(block, key)` | 两个 16 位整数 | 16 位明文整数 |
| `expand_key(key)` | 16 位整数 | `(K0, K1, K2)` |
| `gf_multiply(left, right)` | 两个 4 位整数 | 4 位乘积 |
| `substitute_nibbles(state, inverse=False)` | 16 位状态、逆向标志 | 16 位状态 |
| `shift_rows(state)` | 16 位状态 | 16 位状态；正逆操作相同 |
| `mix_columns(state, inverse=False)` | 16 位状态、逆向标志 | 16 位状态 |
| `trace_block(block, key, decrypt=False)` | 分组、密钥、逆向标志 | `tuple[TraceStep, ...]` |

`TraceStep` 是不可变数据对象，字段为 `operation: str`、`state: int`。轨迹包括输入和每次变换后的结果。

```python
from saes import encrypt_block, decrypt_block, expand_key

key = 0x2D55
plain = 0xA749
cipher = encrypt_block(plain, key)
restored = decrypt_block(cipher, key)
round_keys = expand_key(key)
```

## 4. 编码与填充

`parse_fixed(value, bits, base='hex', name='输入')` 按固定宽度解析字符串，支持 `hex`、`bin`，允许空白及对应进制前缀，但不自动补齐位数。

`parse_hex_bytes(value, name='密文')` 接受非空、偶数个 HEX 字符，可含空白，不接受 `0x` 前缀或标签。`encode_ascii(text)` 严格编码 ASCII，拒绝非 ASCII 字符。

`bytes_to_blocks(data)` 将偶数字节串转为大端 16 位整数列表；`blocks_to_bytes(blocks)` 执行逆转换。空字节串可分组为空列表，但对外密文解密接口拒绝空密文。

`pad_bytes(data)` 和 `unpad_bytes(data)` 固定按 2 字节块实现 PKCS#7。空串追加 `02 02`；奇数长度追加 `01`；偶数长度追加 `02 02`。逆向检查包括分组长度、末字节取值和完整填充内容。

## 5. 多重加密接口

```python
from saes.modes import transform_block, transform_bytes

double_cipher = transform_block(0xA749, 0x2D551234, count=2)
triple_cipher = transform_block(0xA749, 0x2D551234ABCD, count=3)
restored = transform_block(double_cipher, 0x2D551234, count=2, decrypt=True)

cipher_bytes = transform_bytes(b'Hello', 0x2D551234, count=2)
plain_bytes = transform_bytes(cipher_bytes, 0x2D551234, count=2, decrypt=True)
```

- `split_key(key, count)`：`count` 为 1、2、3，组合密钥分别为 16、32、48 位，返回从高位到低位的子密钥元组。
- `transform_block(block, key, count=1, decrypt=False)`：处理单个 16 位分组，不填充。
- `transform_bytes(data, key, count=1, decrypt=False, padding=True)`：处理字节串，仅在所有加密层之前填充一次，所有解密层之后移除一次。
- `padding=False` 时要求调用者提供完整分组，适用于与其他实现核对原始分组结果。

双重为 EE；三重采用 48 位独立子密钥的 EEE。解密分别执行 DD 和 DDD，并逆序使用子密钥。没有实现作业中可选的 32 位三重方案。

## 6. CBC 接口

`cbc_process(data, key, iv, decrypt=False, padding=True)` 返回 `(result_bytes, trace_tuple)`。

`CBCStep` 字段：`index`、`input_block`、`chain`、`intermediate`、`output_block`。加密的中间值是 `Pi XOR chain`；解密的中间值是 `D(Ci)`。

```python
from saes.modes import cbc_process, generate_iv

iv = generate_iv()
cipher, encryption_trace = cbc_process(b'Hello CBC', 0x2D55, iv)
plain, decryption_trace = cbc_process(cipher, 0x2D55, iv, decrypt=True)
```

`generate_iv()` 使用 `secrets.randbits(16)`。IV 不是密钥，但必须保留并共享；当前 API 不把 IV 加入密文数据。

加密：`C0 = E(P0 XOR IV)`，后续 `Ci = E(Pi XOR C[i-1])`。

解密：`P0 = D(C0) XOR IV`，后续 `Pi = D(Ci) XOR C[i-1]`。

`compare_cbc_tampering(ciphertext, key, iv, index, value, replace=False)` 对密文副本操作。`index` 从 0 开始；默认与 `value` 异或，`replace=True` 则整组替换。

返回 `TamperResult`，包含原始解密字节 `original_raw`、篡改密文 `modified_ciphertext`、篡改后解密字节 `modified_raw`、变化分组 `changed_blocks`，以及两份解密数据各自移除填充后的结果或填充错误。字节比较不因填充失败而中断，输入密文不被修改。

## 7. 中间相遇接口

```python
from threading import Event
from saes.attack import meet_in_the_middle

# pairs 应由调用者提供，且所有数据来自相同双重密钥。
# 每个元素是 (16位明文整数, 16位密文整数)。
def search(pairs):
    cancel = Event()
    return meet_in_the_middle(
        pairs,
        progress=lambda stage, done, total: print(stage, done, total),
        cancel=cancel,
    )
```

`meet_in_the_middle(pairs, progress=None, cancel=None)` 返回 `AttackResult`：

| 字段 | 意义 |
| --- | --- |
| `candidates` | 所有已找到的 `(K1,K2)` 候选 |
| `elapsed_seconds` | 搜索耗时 |
| `forward_evaluations` | 建表阶段主分组计算次数 |
| `backward_evaluations` | 反向搜索阶段主分组计算次数 |
| `pair_count` | 使用的已知明密文对数量 |
| `cancelled` | 是否取消，取消时结果不完整 |

先构建 `E_K1(P)` 到所有 K1 的映射，再枚举 `D_K2(C)`。中间值相同的 K1 全部保留，不覆盖碰撞。额外明密文对用于过滤候选。

主枚举规模为 `2 * 2^16` 次基础加／解密，另有候选过滤的计算开销；空间为 `O(2^16)`。界面显示的正反向计数不包括过滤计算。进度按两个各 65,536 步的阶段报告，过滤时间包含在反向阶段，进度百分比不代表精确剩余时间。

GUI 在后台线程调用此函数，以 `Queue` 传递进度和结果，只有主线程修改 Tkinter 组件。取消通过 `threading.Event` 传递，窗口关闭时发出取消信号。

## 9. 操作记录接口

`build_record(operation: str, parameters: dict, result: dict) -> dict` 通过 JSON 序列化复制当时的输入和结果，避免随后修改 GUI 参数或原始字典影响旧记录。支持嵌套 dataclass 和 bytes；bytes 编码为带 `encoding=hex` 标记的对象，dataclass 展开为字段字典，元组转为数组。

记录结构包含 `schema_version=1`、`created_at`（UTC+8）、`project`、`record_type`、`operation`、`parameters` 和 `result`。`record_type` 明确标注其为操作运行记录而非正式验收结论。

`write_record(path, record)` 根据 `.json` 或 `.txt` 扩展名将记录写入 UTF-8 文件，拒绝其他扩展名。文件系统错误抛出 `OSError`，由 GUI 提示；文件选择对话框负责既有文件的覆盖确认。接口不自动创建父目录。

GUI 的 `RecordPanel` 提供四个页面共用的保存入口。各页完成运算后构建快照，保存时不再读取当前输入框。CBC 保存全量轨迹；攻击记录保存全部候选，而非仅界面显示的前 200 个。取消结果带 `search_complete=false`。记录无自动加载或重放执行功能。
