# 用户指南

## 1. 启动程序

在项目目录运行 `python main.py` 或双击 `start.bat`。窗口包含四个功能页，底部状态栏显示当前操作状态。错误会通过对话框提示，并记录在状态栏。

2026-10-27 已通过 31 项本地验收并保存实测数据和截图，详见 `reports/实验报告.md`；真实组间互测与课程提交仍待完成。旧阶段报告记录的是之前的状态。

## 2. 基础加解密

1. 选择数据格式：16 位十六进制或 16 位二进制。
2. 输入明文分组，分别需要 4 个 HEX 字符或 16 个二进制字符。可包含空白分隔及对应的 `0x`、`0b` 前缀。
3. 填写密钥，选择密钥格式 HEX 或 BIN。基础密钥分别需要 4 个 HEX 字符或 16 个二进制字符，前导零不能省略。
4. 点击“加密”。结果框显示 HEX、BIN、轮密钥，下面的表格显示每一步状态及其矩阵。
5. 点击“回填上次密文”，保留加密时的方案与密钥，再点击“解密”。

“载入示例”会填入明文 `A749`、密钥 `2D55`。点击“复制结果”可复制结果框内容，用于整理后续测试记录。计算轨迹在表格中滚动查看。

## 3. ASCII 字符串

1. 数据格式选择“ASCII 字符串 / HEX 密文”。
2. 加密时输入 ASCII 明文，可以包含空格、换行和 ASCII 控制字符；中文、表情等非 ASCII 内容会提示错误。
3. 点击“加密”，从结果中获取 HEX 密文。程序同时显示字节转义形式，便于查看不可打印字节。
4. 点击“回填上次密文”后解密，或手工粘贴 HEX 密文。HEX 字节间可添加空白，但不要粘贴“结果 HEX：”等标签。

字符串按大端字节序，每 2 字节一组。例如 `AB` 对应分组 `4142`。

程序使用 PKCS#7 填充：奇数字节追加 `01`；偶数字节（包括空串）追加 `02 02`。因此空明文也会产生一个密文分组。解密后检查并移除填充，保留原始尾部空格和换行。

单分组模式与字符串模式的填充约定不同。例如单分组 `4142` 与字符串 `AB` 不会产生相同长度的密文。

## 4. 双重与三重加密

在“双重 / 三重加密”页选择方案：

| 方案 | 密钥 HEX 长度 | 加密顺序 |
| --- | --- | --- |
| 双重 | 8 个字符 | 先 K1，再 K2 |
| 三重 | 12 个字符 | 先 K1，再 K2，最后 K3 |

例如双重密钥 `2D551234` 拆分为 `K1=2D55`、`K2=1234`。三重密钥 `2D551234ABCD` 再增加 `K3=ABCD`。

支持单分组和 ASCII 字符串。加密多次只对原始明文进行一次填充，不在每层重复填充。解密按相反的子密钥顺序执行，完成全部解密后再移除填充。

切换方案不会覆盖已输入的密钥，应自行调整密钥长度或点击“载入示例”。

## 5. 中间相遇攻击

本页针对双重加密，不用于三重加密。

1. 每行输入一组已知数据：`明文HEX 密文HEX`，两者均为 4 个 HEX 字符。
2. 所有数据必须来自同一组双重密钥，建议使用至少 3 个不同明文。
3. 可填写 8 位 HEX 演示密钥并点击“生成演示明密文对”。它只构造数据，不会自动运行攻击，也不会把该密钥传入搜索函数。
4. 点击“开始中间相遇搜索”。程序先枚举全部 K1 建表，再枚举全部 K2 匹配，并使用额外明密文对过滤候选。
5. 运行时可查看进度或点击“取消”。取消结果是部分搜索，不能用于判断密钥唯一性。
6. 界面最多展示前 200 个候选；点击“导出全部候选 CSV”可以保存全部候选。CSV 中的 `search_complete` 标记搜索是否完整。

单组明密文通常会对应多个组合密钥，不能将第一个匹配结果直接认定为原始密钥。即使若干对下只剩一个候选，也仅表示在当前已知数据及完整枚举范围内唯一。

## 6. CBC 加解密

1. 填入 4 位 HEX 密钥和 4 位 HEX IV。
2. 点击“生成随机 IV”可使用系统随机源重新生成 16 位 IV。每次加密后都应记录当次 IV；后续解密不能重新随机生成 IV。
3. 在左侧输入 ASCII 明文，点击“加密明文 → 密文”。右侧会填入 HEX 密文，结果区显示分组计算轨迹。
4. 解密时保持原密钥和 IV，或粘贴对方的 HEX 密文并填写相应参数，点击“解密密文 → 明文”。

IV 不包含在密文字符串中，需要独立共享。CBC 沿用 2 字节分组和 PKCS#7 填充。为了复现实验，“载入示例”使用固定 IV `1234`；它是示例参数。

## 7. CBC 篡改比较

1. 先生成或粘贴 CBC 密文。
2. 填写要修改的密文分组序号，从 `0` 开始。
3. 选择“异或掩码”或“整组替换”，输入 4 位 HEX 值。
4. 点击“篡改并比较”。

程序会对密文副本进行修改，展示修改后的密文、原始与篡改后的解密分组、XOR 差值、变化分组序号及填充状态。原密文输入不会被覆盖。

实验比较使用保留填充的原始解密字节。即使修改末分组破坏了填充，也能观察结果。修改 `Ci` 会改变 `Pi`，并在存在下一分组时对 `Pi+1` 产生相同的 XOR 改变量；后面的其他分组保持不变。

填充合法不等于密文未经修改。当前 CBC 用于课程实验，未添加消息认证。

## 8. 常见问题

- **提示长度不符**：补齐前导零，核对 HEX/BIN 选项以及组合密钥长度。
- **填充无效**：核对加密方案、密钥、IV、完整密文和双方填充规则。
- **结果不是 ASCII**：可能使用了错误参数，或者输入的密文原本不是本项目的 ASCII 文本加密结果。可查看 HEX 和字节转义。
- **Tkinter 导入失败**：Python 安装缺少 Tcl/Tk，需通过安装程序补齐。
- **中间相遇候选很多**：添加其他明文对应的密文对，保证它们使用同一组密钥。
- **跨组字符串解密失败**：先确认算法基础分组一致，再确认字节序、填充、密文编码、密钥拆分和三重加密顺序。

## 9. 保存实验操作记录

基础、多重加密和 CBC 页提供“保存记录”按钮；中间相遇页提供“保存搜索记录”。完成一次计算后点击按钮，选择 JSON 或文本格式，默认目录为项目的 `reports` 文件夹。建议为不同操作起不同文件名。

记录包含操作时间（UTC+8）、操作种类、当时使用的输入参数、输出与轨迹。基础及多重字符串的轨迹仅记录首分组，与界面一致；CBC 保存全部分组轨迹；攻击保存全部候选和完整／取消状态。

记录保存的是上次成功计算的快照。之后修改密钥、IV、输入框或回填密文不会改写旧快照；需要点击计算生成新记录。输入错误不会生成新记录，之前成功的记录仍可保存。搜索开始时清除上次搜索记录，运行期间不可导出搜索记录，结束或取消后才能保存。

JSON 适合后续程序处理；文本适合直接阅读。字节数据在结构化结果中以 `{"encoding": "hex", "data": "..."}` 表示；轨迹中的整数状态为十进制数，其 HEX 展示可以在结果摘要中查看或自行转换。

记录会包含本次课程实验使用的密钥和数据，保存至你选择的本地位置。它是一次运行的数据，**不是正式验收通过结论**；本次本地验收数据已在 `reports/实验报告.md` 汇总，真实组间互测仍需补充。导出不包含截图，不自动上传或提交。
